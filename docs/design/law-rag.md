# 법령 근거 Q&A (RAG) 설계 — 프로토타입

작성 2026-11-24 · 담당 정준영 (M7 확장)

## 왜

계약서 Q&A(M7)는 사용자 계약서와 표준계약서만 근거로 답했다. "2차적저작물 작성권은 누구에게 있나요?",
"서면 계약을 안 쓰면 어떻게 되나요?" 같은 질문은 법에 정해진 내용이라 계약서만으로는 답이 비어 있다.
법령 전문을 프롬프트에 다 넣을 수는 없으므로(저작권법만 조문 200개) 질문과 관련된 조문만 찾아 넣는다.

## 흐름

```
[색인 만들 때, 손으로 한 번]
data/law/targets.yaml ─▶ 법제처 Open API (lawSearch → lawService) ─▶ 조문 단위 LawArticle
                                                                    └▶ Upstage embedding-passage
                                                                    ═▶ data/law/index.json (gitignore)

[질문할 때]
질문 ─▶ BM25(2글자 묶음) 순위 ┐
     └▶ embedding-query 코사인 ┴▶ 관련성 기준 통과? ─ 아니면 법령 없이 답 (지금과 같음)
                                   └ 통과 ▶ RRF로 섞어 상위 3개 ▶ 프롬프트 "관련 법령 (참고)" 블록
LLM 답 ─▶ 인용문이 조문 원문에 글자 그대로 있는지 코드로 확인 (없으면 버림) ─▶ 화면
```

| 부분 | 파일 |
|---|---|
| 법제처 수집·파싱 | `backend/src/openbook/law/lawgo.py` |
| 임베딩 | `backend/src/openbook/law/embed.py` |
| 색인·검색 | `backend/src/openbook/law/index.py` |
| 색인 만들기 CLI | `backend/src/openbook/law/__main__.py` |
| Q&A 연결 | `qa/answer.py`, `qa/prompt.py`, `api/routes/ai.py` (`get_law_search`) |
| 화면 | `frontend/src/app/qa/page.tsx` (법령명·조문·시행일·국가법령정보센터 링크) |

## 대상 법령 (후보 — 허정민 님 확인 필요)

저작권법(200), 만화진흥에 관한 법률(20), 예술인의 지위와 권리의 보장에 관한 법률(41), 예술인 복지법(35),
콘텐츠산업 진흥법(61). 괄호는 2026-11-24 받은 현행 조문 수 (장 제목·삭제 조문 제외), 합계 357개.
소득세법(원천징수)은 넣지 않았다 — 원천징수는 계산 엔진(R11)이 맡고, Q&A는 계산하지 않는다.

## 검색

- **조문 하나 = 검색·인용 한 단위.** 항·호·목은 이어 붙인다. id는 `l-저작권법-제22조`.
- **글자 겹침: 2글자 묶음 BM25** (k1 1.2, b 0.75). 조문 제목은 두 번 센다.
  처음엔 겹치는 묶음 수를 그대로 셌는데, 긴 조문(제2조 정의)이 거의 모든 질문에서 위로 올라왔다.
- **임베딩: Upstage `embedding-passage`(조문) / `embedding-query`(질문)**, 4096차원, 코사인.
- **RRF(k=60)** 로 두 순위를 섞어 상위 3개.
- **관련성 기준.** 법이 다루지 않는 질문(원천징수, MG 지급일)에 엉뚱한 조문을 붙이지 않는다.
  - 임베딩이 있으면: 가장 가까운 조문의 코사인 < 0.3 이면 법령 없음
  - 임베딩 호출 실패·키 없음: BM25 최고 점수 < 10 이면 법령 없음
- **색인 파일이 없으면** 법령 검색을 끈다. Q&A는 이전과 똑같이 계약서·표준계약서로만 답한다.

### 잰 값 (질문 11개, 2026-11-24)

| 질문 | 혼합 검색 상위 3 | 판단 |
|---|---|---|
| 2차적저작물 작성권은 누구에게? | 저작권법 제22조, 제5조, 제45조 | 좋음 |
| 출판권 존속기간은? | 제59조(배타적발행권 존속기간), 제39조, 제41조 | 좋음 |
| 예술인에게 불공정한 계약을 강요하면? | 예술인지위법 제13조(불공정행위 금지), 제14조, 예술인복지법 제4조의4 | 좋음 |
| 서면 계약을 안 쓰면? | 예술인복지법 제4조의4, 제18조(과태료), 제5조의2 | 좋음 |
| 저작인격권을 양도할 수 있나? | 저작권법 제15조, 제14조(일신전속성), 제45조 | 보통 (제14조가 1위였으면) |
| 저작권 양도 계약은 어떻게 해석? | 제45조, 제62조, 제101조 | 보통 |
| 웹툰을 드라마로 만들 때 허락? | 만화진흥법 제2조, 저작권법 제63조, 제57조 | 약함 (제99조 영상화가 빠짐) |
| 수익 배분 내역을 요구할 수 있나? | 예술인지위법 제13조, 예술인복지법 제4조의4, 저작권법 제108조의3 | 보통 |
| 계약 기간이 끝나면 연재 작품은? | 저작권법 제40조, 예술인복지법 제4조의4, 저작권법 제3조 | 약함 |
| 정산서에 원천징수 세율이 틀렸어요 | (법령 없음) | 좋음 |
| MG는 언제 지급되나요? | (법령 없음) | 좋음 |

코사인 분포: 관련 질문의 최고값 0.31~0.59, 무관 질문 0.19~0.23. 기준 0.3은 그 사이.
엉뚱한 조문이 섞여도 LLM이 인용하지 않으면 화면에 나오지 않고, 인용해도 원문 그대로여야 남는다.

## 안전장치 (기존 Q&A 원칙 그대로)

- 프롬프트 규칙: 법령(id `l-`)은 질문이 법에 정해진 권리·의무를 물을 때만 인용하고, 이 계약에 어떻게
  적용되는지는 판단하지 않는다. 조문에 적힌 내용만 옮긴다.
- 인용문은 조문 원문에 글자 그대로 있어야 남는다 (`_verified_citations`). 지어낸 인용은 버린다.
- 답의 숫자는 인용문·질문·조문 번호에 있는 것만 허용 (`_numbers_supported`).
- 화면에 법령명·조문 번호·**원문 시행일**·국가법령정보센터 링크를 함께 보여 준다.
  색인은 만든 날의 현행 원문이므로, 개정 뒤에는 링크로 현행 원문을 확인하게 한다.
- 화면 문구: "법령 조문은 적힌 내용만 옮긴 것이고, 이 계약에 어떻게 적용되는지는 판단하지 않습니다."
- LAW_OC·UPSTAGE_API_KEY는 `.env`에만 두고 로그·오류 문구에 넣지 않는다. 질문 원문도 오류에 넣지 않는다.

## 돌리는 법

```
# .env에 LAW_OC=..., UPSTAGE_API_KEY=... (값은 커밋하지 않는다)
backend/.venv/Scripts/python -m openbook.law build             # 1~2분, data/law/index.json (약 30MB)
backend/.venv/Scripts/python -m openbook.law search "질문"     # 검색만 확인
```
`--no-embed`로 만들면 임베딩 없이 BM25만 쓴다. 다른 경로는 `LAW_INDEX_PATH`.
API 서버는 시작 뒤 처음 질문할 때 색인을 읽는다 (색인을 다시 만들면 서버를 다시 켠다).

## 실제 화면 확인 (2026-11-24, 데모 1 계약서, Solar Pro 4)

| 질문 | 결과 |
|---|---|
| 저작인격권을 양도할 수 있나요? | 저작권법 제14조(일신전속성)를 글자 그대로 인용해 답함 |
| 2차적저작물 작성권은 누구에게 있나요? | 표준계약서 제14조만 인용 (법령은 후보로 들어갔지만 LLM이 표준계약서를 골랐음) |
| 서면 계약서를 안 쓰면 법적으로 어떻게 되나요? | 예술인 복지법 제4조의4 인용은 나옴. 답 문장에 금지 표현이 들어가 템플릿 문장으로 바뀜 |
| 정산서에 원천징수 세율이 틀렸어요 | 법령을 붙이지 않고 '근거 조항을 찾지 못함' |

법령 원문에는 '위반'·'손해' 같은 말이 많아서 LLM이 답 문장에 옮기면 금지 표현 필터에 걸린다.
프롬프트에 쓰지 말라고 적었지만 완전히 막지는 못한다. 걸리면 템플릿 문장 + 원문 인용으로 안전하게 나간다.

## 한계와 다음

- 질문 11개로 잰 프로토타입이다. 정답 조문을 붙인 평가 질문 30~50개를 만들어 기준값·가중치를 다시 잰다.
- 판례·해석례·고시(예: 표준계약서 고시)는 아직 없다.
- 색인 갱신은 손으로 한다. 법령 개정 확인(법령 시행일 비교) 후 다시 만드는 작업을 정기 실행으로 붙일 수 있다.
- 배포 서버에는 색인 파일을 따로 올려야 한다 (저장소에 넣지 않음). 운영에서는 pgvector로 옮기는 것을 검토.
- 대상 법령 목록(`data/law/targets.yaml`)은 허정민 님 확인 필요.
