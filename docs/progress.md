## 정한 것 (바꾸려면 팀 합의)

- **LLM은 금액을 계산하지 않는다.** 계산은 규칙 엔진(Decimal), LLM은 조건 찾기·원문 인용·Q&A만.
- **AI가 찾은 조건은 사용자가 확정해야 계산에 쓴다.** 처리중에는 확정을 받지 않는다.
- **판단하지 않는다.** '위반·부당·불리·유리' 같은 표현은 필터로 막고, 차이는 플랫폼에 보낼 확인 질문으로 바꾼다.
- **틀린 숫자보다 계산 안 함.** 구간별 RS·빠진 정산 기간(후차감)·순매출 기준인데 회사입금액 없음 → 계약 전체 금액 숨김 (R10).
- **원천징수는 사업소득 3.3% 고정**, 소액부징수 없음 (허정민 님 확정 2026-11-25). 결과 화면에 기준을 적는다.
- **법령은 '적힌 내용'만 인용**하고 계약에 어떻게 적용되는지 판단하지 않는다. 시행일과 국가법령정보센터 링크를 함께 보인다.
- **배포는 Vercel** (화면·API 프로젝트 2개 + Neon Postgres). 비밀 값(UPSTAGE_API_KEY, LAW_OC)은 `.env`·Vercel 환경변수에만. 실제 계약서·정산서는 `data/private/`에만.

## 허정민 님 답 (2026-11-25, 반영 완료)

1. 원천징수: **3.3%로만** (날짜별 세율 없음) → `rules.py` 확정
2. 소액부징수: **넣지 않음**
3. 별도 계약의 빠진 달: **계산하고 질문만** (지금 방식이 맞음)
4. 공제 항목: **정확한 값과 1원 미만 차이면 같은 것** → R13 추가
5. 법령: 지금 5개 + **약관법**, **소득세법(원천징수 조문)**. 하도급법·대중문화예술산업발전법은 넣지 않음. 표준계약서는 고시로 구분 표시
6. 원천징수 선택: **3.3% 고정 + '3.3% 기준' 표기로 충분**

계산 규칙 버전: `draft-2026-11-23-r12` → **`2026-11-25-r13` (확정)**. 결과 화면의 '임시 안' 문구는 더 이상 안 나온다.

## 알려진 한계

- 법령 Q&A 답 문장에 금지 표현이 들어가면 '○○법 제○조에 관련 내용이 있습니다' 안내 문장으로 바뀐다 (인용은 그대로).
- '~해야 하나요?/필요한가요?'처럼 적용 판단을 묻는 질문은 법령 후보가 있어도 '찾지 못함'으로 답할 수 있다.
- 법령 검색 평가 세트·홀드아웃은 모두 정준영 초안이다 (검토 필요).
- 법령 색인은 만든 날의 현행 원문이다. 개정되면 `python -m openbook.law build`로 다시 만든다.
