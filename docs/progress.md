## 정한 것 (바꾸려면 팀 합의)

- **LLM은 금액을 계산하지 않는다.** 계산은 규칙 엔진(Decimal), LLM은 조건 찾기·원문 인용·Q&A만.
- **AI가 찾은 조건은 사용자가 확정해야 계산에 쓴다.** 처리중에는 확정을 받지 않는다.
- **판단하지 않는다.** '위반·부당·불리·유리' 같은 표현은 필터로 막고, 차이는 플랫폼에 보낼 확인 질문으로 바꾼다.
- **틀린 숫자보다 계산 안 함.** 구간별 RS·빠진 정산 기간(후차감)·순매출 기준인데 회사입금액 없음 → 계약 전체 금액 숨김 (R10).
- **원천징수는 사업소득 3.3% 고정** (MVP). 결과 화면에 기준을 적는다. 8.8% 등 선택은 허정민 님 답 뒤 결정.
- **법령은 '적힌 내용'만 인용**하고 계약에 어떻게 적용되는지 판단하지 않는다. 시행일과 국가법령정보센터 링크를 함께 보인다.
- 비밀 값(UPSTAGE_API_KEY, LAW_OC)은 `.env`에만. 실제 계약서·정산서는 `data/private/`에만.

## 허정민 님 확인 대기

`docs/calc-rules/확인요청_2026-11-24.md` (보낼 메시지 초안)
1. 원천징수율이 날짜에 따라 바뀌는지 (날짜별 표는 만들어 둠)
2. 소액부징수(소득세 1,000원 미만 면제) 넣을지
3. 별도 계약의 빠진 달을 계산 불가로 볼지 (지금은 질문만)
4. 공제 항목 1원 차이를 같은 것으로 볼지
5. 법령 RAG 대상 법령 목록, 평가 세트 검토
6. 원천징수 선택(3.3%/8.8%)이 필요한지

답이 오면: `engine/rules.py` 반영 → `RULES_VERSION`을 `draft-…`에서 확정으로 → 손계산 케이스 추가.

## 알려진 한계

- 법령 Q&A 답 문장에 법령 원문의 '위반' 같은 말이 들어가면 기본 문구로 바뀐다 (인용은 그대로 나옴).
- 법령 색인은 만든 날의 현행 원문이다. 개정되면 `python -m openbook.law build`로 다시 만든다.
- 조건 화면은 계약서 처리중에 직접 URL로 열면 빈 조건이 보인다 (저장은 막혀 있음).
