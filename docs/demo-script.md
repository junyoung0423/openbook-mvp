# 심사 데모 시나리오 (5–7분)

자료: `data/samples/demo/` (모두 가상 계약서·정산서). 기대 값: `data/samples/demo/README.md`.
2026-11-24 리허설: 데모 2를 화면으로 처음부터 끝까지 돌림 (계약서 처리 약 20초), 데모 1·3 결과 화면 확인.

## 0. 준비 (전날)

1. `.env`에 `UPSTAGE_API_KEY`, `LAW_OC`, `OPENBOOK_AUTH_DISABLED=1` (값은 공유·커밋하지 않는다)
2. DB 최신화: `backend/.venv/Scripts/alembic -c backend/alembic.ini upgrade head`
3. 법령 색인: `data/law/index.json`이 없으면 `python -m openbook.law build` (1–2분)
4. 서버: `.claude/launch.json`의 `api`, `web` 켜기 → http://localhost:3000
5. **예비 데이터**: `python backend/scripts/seed_demo.py --skip-last 1`
   - 데모 1(6월 빼고)·2·3이 확정된 상태로 들어간다. 현장에서 AI 호출이 느리거나 실패하면 이것으로 진행
   - 데모 1의 6월은 현장에서 붙여넣기로 넣어 "붙여넣기 → 자동 채움"을 보여 준다

## 1. 문제 (30초)

"웹툰 작가는 정산서를 받아도 계약서대로 계산된 건지 확인할 방법이 없습니다.
MG 회수, 공제, 배분율, 원천징수가 겹쳐서 손으로 계산하기 어렵습니다."

## 2. 계약서 → 조건 (1분 30초) — 데모 2 「바다 끝 우체국」

1. 첫 화면 → 본문 붙여넣기 → `demo2_contract.txt` 붙여넣기 → 동의 체크 → 올리기 (약 20초)
2. 조건 화면이 자동으로 열림. 보여 줄 것:
   - AI가 찾은 값마다 **근거 조항 원문**이 붙어 있음 (계약금 1,000,000원 → 제3조 원문)
   - "MG 회수 방식 = 별도 처리" ← 제3조 ②항 "차감하지 않는다"
   - **사용자가 체크해야 계산이 열림** (AI 값을 그대로 믿지 않는 구조)
3. 필수 5개 체크 → 저장

말할 것: "AI는 조건을 찾아 원문과 함께 보여 줄 뿐이고, 계산은 사용자가 확인한 값으로만 합니다."

## 3. 정산서 → 대조 (2분) — 데모 2 계속, 그다음 데모 1

1. 정산서 화면 → `demo2_statements.txt` 1월 블록 붙여넣기 → "표에서 값 읽기" → 칸이 자동으로 채워짐 → 저장. 2월도 같게.
2. 대조 결과:
   - 1월: 모두 0원 차이
   - **2월: 작가지급액 −24,430원.** 정산액은 맞는데 원천징수가 39,080원 (3.3%면 14,650원)
     → "플랫폼이 8.8%로 뗀 것으로 보입니다" 대신 화면은 **확인 질문**만 띄움:
     "원천징수 금액이 어떻게 계산되었는지 세율과 기준 금액을 알려 주실 수 있을까요?"
   - 계산 내역을 펼쳐 **한 줄씩 식과 근거 조항**이 있음을 보여 줌
3. 데모 1 「새벽 정원」 결과 (예비 데이터로 3–5월이 들어 있음, 6월은 현장에서 붙여넣기):
   - 3·4월: MG 3,000,000원이 몫에서 회수되며 남은 MG가 줄어듦 (2,090,000 → 725,000)
   - 5월: MG 회수 끝, 작가지급액 −95,000원
   - **6월: 계약서에 없는 '운영 대행 비용' 100,000원** → 정산액 −65,000원, 확인 질문
     "'운영 대행 비용' 공제는 계약서의 어느 조항에 근거한 것인지 알려 주실 수 있을까요?"

말할 것: "계산은 LLM이 아니라 규칙 엔진이 합니다. 손계산 케이스 20개와 1원까지 같게 맞췄습니다.
판단(부당하다, 위반이다)은 하지 않고 플랫폼에 보낼 질문으로 바꿔 줍니다."

## 4. 계산 불가 (30초) — 데모 3 「여름의 끝에서」

구간별 RS 계약 → "계산 불가: RS율이(가) 구간별이라 계산하지 않음", **금액을 하나도 보여 주지 않음**.
말할 것: "틀린 숫자를 보여 주느니 계산하지 않습니다."

## 5. 계약서 Q&A + 법령 근거 (1분) — 데모 1 '질문하기'

안정적으로 나오는 질문 (2026-11-24 확인):

| 질문 | 나오는 근거 |
|---|---|
| 선급금(MG)은 얼마이고 어떻게 회수하나요? | 내 계약서 제4조(선급금) 원문 |
| 저작인격권을 양도할 수 있나요? | 저작권법 제14조(일신전속성), 시행일·국가법령정보센터 링크 |
| 2차적저작물 작성권은 누구에게 있나요? | 표준계약서 제14조 (고시 번호 표시) |
| 정산서에 원천징수 세율이 틀렸어요 | "근거 조항을 찾지 못했습니다" (법령을 억지로 붙이지 않음) |

피할 질문: "서면 계약서를 안 쓰면 어떻게 되나요?" — 인용은 맞게 나오지만 답 문장이 금지 표현 필터에 걸려
기본 문구로 바뀐다 (안전 동작이지만 데모로는 밋밋함).

말할 것: "답에 쓰인 원문은 코드가 원문과 글자 단위로 대조합니다. 지어낸 인용은 화면에 나오지 않습니다."

## 6. 마무리 (30초)

- 계산 규칙: 허정민 님 규칙 R1–R12, 손계산 20케이스 통과 (`backend/tests/test_calc_cases.py`)
- 법령: 법제처 Open API 5개 법령 357개 조문, 하이브리드 검색
- 한계: 원천징수 3.3% 고정, 구간별 RS 미지원, 법령 검색은 질문 11개로만 잰 프로토타입
