## 1. 목표와 범위

### 목표
기능은 모두 연결돼 있습니다(업로드 → 조건 확인 → 정산서 입력 → 대조 결과 → Q&A). 지금 화면은 기본 Tailwind 카드 상태라서, **심사 데모에서 신뢰감 있게 보이고 작가가 혼자서도 흐름을 따라갈 수 있게** 디자인을 입힙니다.

### 범위
- **바꾸는 것**: `frontend/` 안의 화면 구조, 스타일, 공용 컴포넌트, 입력 표시 형식
- **바꾸지 않는 것**: `backend/` 전체, API 경로·요청·응답 모양, `backend/src/openbook/schemas/`, 서버가 만든 문장(`summary`, `questions`, `notice`, `diff_meaning`, `answer`)의 내용
- 각 화면의 **데이터 흐름 로직**(`save()`, `submit()`, `waitUntilProcessed()`, 폴링, 오류 처리)은 그대로 둡니다. 화면 표시만 바꿉니다. 로직을 바꿔야 할 것 같으면 멈추고 PR 본문의 "결정 필요"에 적습니다.

### 우선순위 (심사 데모 기준)
1. 공용 기반(폰트, 디자인 토큰, 공용 컴포넌트, 상단 바·단계 표시)
2. **대조 결과** 화면 — 데모의 하이라이트
3. **조건 확인** 화면
4. 정산서 입력 화면
5. 첫 화면(업로드·내 계약서), Q&A, 로그인

## 3. 디자인 방향

### 콘셉트: "펼친 장부"
오픈북은 작가가 매달 정산서를 펼쳐 계약서와 맞춰 보는 도구입니다. **차분하고 정확한 종이 장부** 느낌으로 갑니다.
- 따뜻한 종이색 배경 위에 흰 카드, 잉크색 글자
- 숫자는 **고정폭 숫자(tabular-nums), 오른쪽 정렬**로 장부처럼 줄이 맞게
- 계약서 원문 인용은 **종이 메모처럼** 구분된 블록
- 브랜드 색은 지금 쓰는 짙은 청록(`teal-900`)을 유지하고, **버튼·링크·현재 단계 표시에만** 씁니다. 결과 숫자에는 쓰지 않습니다
- 장식(그라데이션, 일러스트, 이모지)은 넣지 않습니다

### 디자인 토큰 (`frontend/src/app/globals.css`의 Tailwind v4 `@theme`에 정의)

| 토큰 | 값 | 쓰는 곳 |
|---|---|---|
| `--color-paper` | `#F7F5F0` | 페이지 배경 |
| `--color-surface` | `#FFFFFF` | 카드 |
| `--color-line` | `#E5E1D8` | 테두리, 구분선 |
| `--color-ink` | `#1C1B19` | 본문 글자 |
| `--color-muted` | `#6B675F` | 보조 글자, 설명 |
| `--color-brand` | `#134E4A` | 주요 버튼, 링크, 현재 단계 |
| `--color-brand-soft` | `#E7F0EE` | 현재 단계 배경, 선택된 칩 |
| `--color-quote` | `#FAF8F3` | 원문 인용 블록 배경 |
| `--color-error` | `#B42318` | **입력 오류·네트워크 오류 문구에만.** 금액·차이·조건 상태에는 절대 쓰지 않음 |

- 다크 모드는 이번에 하지 않습니다. `globals.css`의 `prefers-color-scheme: dark` 블록은 지웁니다(지금도 화면이 밝은 색을 하드코딩하고 있어 섞이면 깨짐).
- 모서리: 카드 `16px`, 입력·버튼 `10px`. 그림자: 카드에 아주 옅게(`0 1px 2px rgb(0 0 0 / 0.04)`) 한 단계만.
- 간격: 카드 안쪽 24px(모바일 16px), 카드 사이 16px.

### 글꼴
- **Pretendard Variable**을 `next/font/local`로 넣습니다 (`pretendard` npm 패키지의 woff2 사용). 지금 쓰는 Geist는 영문 전용이고, `globals.css`의 `font-family: Arial`이 덮어쓰고 있어 한글이 시스템 기본 글꼴로 나옵니다. `next/font/google` import와 Arial 지정을 모두 지웁니다.
- 숫자에는 `font-variant-numeric: tabular-nums` 유틸리티(`.num`)를 만들어 금액 칸 전부에 적용합니다.
- 글자 크기: 페이지 제목 28 / 섹션 제목 20 / 카드 제목 17 / 본문 16 / 보조 14 / 아주 작은 안내 13. 본문 줄 간격 1.6.

## 4. 공용 컴포넌트

`frontend/src/components/`에 만듭니다. 새 UI 라이브러리(shadcn, MUI 등)는 들이지 않습니다. 아이콘이 필요하면 `lucide-react`만 허용하고, **판단을 암시하는 아이콘(체크, 경고 삼각형, X)은 결과·조건 상태에 쓰지 않습니다.**

| 컴포넌트 | 역할 |
|---|---|
| `AppShell` | 상단 바(왼쪽 "오픈북" 워드마크 → `/`, 가운데 현재 계약서 이름, 오른쪽 로그인 정보·로그아웃 또는 "로컬 모드") + 본문 폭 제한. 모든 화면이 이걸로 감쌉니다 |
| `StepNav` | 계약서 id가 있는 화면 상단의 단계 표시. 아래 별도 설명 |
| `Card`, `CardHeader` | 흰 카드와 제목 줄 |
| `Button` | `primary` / `secondary` / `ghost`(삭제 같은 덜 중요한 동작) 세 종류, `disabled`일 때 이유 문구를 옆에 보여 줄 수 있게 |
| `MoneyInput` | 금액 입력. 아래 별도 설명 |
| `RateInput` | 비율 입력(% 단위). 아래 별도 설명 |
| `StatusBadge` | `추출됨` / `찾지 못함` / `직접 입력`. **색이 아니라 모양으로 구분**: 추출됨 = 옅은 회색 채움, 찾지 못함 = 점선 테두리, 직접 입력 = 실선 테두리. 모두 잉크·muted 색 |
| `SourceQuote` | 근거 원문 블록. 위에 "근거 · 제3조 (계약금)" 라벨, 본문은 `whitespace-pre-wrap`, 왼쪽 2px brand 선, `quote` 배경. 6줄 넘으면 접고 "전체 보기" |
| `Notice` | 고정 안내(회색 작은 글씨 박스) |
| `InfoPanel` | `계산 불가`, 처리 중 같은 안내. **노란색·빨간색 경고 박스가 아니라** 테두리 있는 중립 박스 |
| `EmptyState` | 빈 상태(안내 문장 + 다음 행동 버튼 1개) |
| `Spinner` / `ProcessingState` | 처리 중 표시(문장 + 걸리는 시간 안내) |

### StepNav
- 단계: **① 계약서 → ② 조건 확인 → ③ 정산서 입력 → ④ 대조 결과**, 오른쪽 끝에 별도 링크 **"계약서에 질문하기"**
- 지금 화면이 어느 단계인지 brand 색으로 표시
- `GET /contracts/{id}`의 `status`(`처리중` / `조건 확인 대기` / `확정` / `처리 실패`)로 잠금 표시: `확정`이 아니면 ③④는 회색으로 두고 "조건을 확정하면 열립니다" 안내 (링크는 막지 않아도 됨 — 결과 화면이 이미 `TERMS_NOT_CONFIRMED`를 처리함)
- 모바일(640px 미만)에서는 "2 / 4 조건 확인"처럼 한 줄로 줄이고, 누르면 단계 목록이 펼쳐짐
- 이 호출 하나 외에 새 API 호출을 늘리지 않습니다

### MoneyInput (금액)
- 화면에는 `3,000,000` 처럼 콤마를 넣어 보여 주고 오른쪽에 `원`을 붙입니다
- **상태로 들고 있는 값과 서버로 보내는 값은 지금처럼 콤마 없는 문자열**(`"3000000"`)입니다. 입력 중 콤마·공백을 문자열로 지우고, 숫자·소수점·(허용할 때만) 맨 앞 `-` 외의 글자는 막습니다
- `allowNegative` 옵션(정산서 매출액·회사입금액·정산액은 음수 허용, 지금 `SIGNED_MONEY` 규칙과 동일)
- 붙여넣기한 `1,234,567원`도 받아들이게
- `Number`로 바꾸지 않습니다

### RateInput (비율)
- 작가는 `65`를 입력하고 화면에는 `65 %`, 서버로는 지금처럼 `"0.65"`를 보냅니다
- 변환은 **문자열로 소수점을 두 자리 옮기는 순수 함수**로 만듭니다: `percentToRate("65") === "0.65"`, `percentToRate("6.5") === "0.065"`, `percentToRate("100") === "1"`, `rateToPercent("0.65") === "65"`, `rateToPercent("0.065") === "6.5"`. 0~100 밖, 빈 문자열, 숫자 아닌 값은 `null`
- 조건 화면의 RS 배분율과 공제 항목 비율에 씁니다. 안내 문구 "0~1, 예: 60%는 0.6"은 지웁니다

### 형식 함수 (`frontend/src/lib/format.ts`)
- `won()`은 그대로 두거나 이쪽으로 옮기고, `stripMoney`, `formatMoneyInput`, `percentToRate`, `rateToPercent`를 추가
- 이 함수들은 틀리면 금액이 틀어지는 곳이라 **테스트를 붙입니다.** `vitest`를 devDependency로 추가하고 `frontend/src/lib/format.test.ts`만 둡니다(화면 테스트는 이번 범위 아님). 위 예시 + 경계값(`"0"`, `"0.5"`, `"99.99"`, `"100.1"`, `"abc"`, `"-5"`)을 넣고, `package.json`에 `"test": "vitest run"`, CI 프런트엔드 job에 `npm test` 추가

## 5. 화면별 지시

### 5-1. 대조 결과 `/results` (가장 중요)

지금 문제: 핵심 숫자(차이)가 긴 문장과 표 안에 묻혀 있고, 계산 내역 12줄이 기본으로 펼쳐져서 4개월치면 화면이 4,000px가 넘습니다. 모바일(390px)에서는 표가 잘려 **정산서·차이 칸이 안 보입니다.**

**구조 (위에서 아래로)**
1. **머리 카드**: 제목 "정산 대조 결과", 계약서 이름, 그 아래 `diff_meaning` 한 줄. 원천징수 기준 설명(3.3%, 기타소득이면 차이 날 수 있음)은 `Notice`로 접어서 "계산 기준 보기"
2. **기간 바로가기 칩**(기간이 2개 이상일 때): `3월 · 4월 · 5월 · 6월` 처럼 가로로, 누르면 해당 기간 카드로 스크롤. 각 칩에 작은 글씨로 `차이 0원` / `차이 -95,000원`을 **같은 색으로** 표시. (차이가 0인지 보는 것은 문자열 비교 `/^-?0(\.0+)?$/`로. 금액 계산 아님)
3. **`unsupported_reason`이 있으면** 맨 위에 `InfoPanel`(중립 박스): 이유 문장 + "틀린 숫자를 보여 드리지 않으려고 금액을 계산하지 않았습니다…" 문장 유지. 금액은 하나도 보이지 않게(지금 동작 유지)
4. **기간 카드** (기간마다 하나)
   - 제목: `2027년 5월` 처럼 읽기 쉽게(기간이 한 달 전체가 아니면 `2027-05-01 ~ 2027-05-20` 그대로). 날짜 문자열 조작으로만
   - **세 숫자 줄** (작가지급액 기준): `계약서 기준` / `정산서` / `차이` 세 칸을 같은 높이의 칸으로 나란히. 숫자는 28px 굵게, `.num`. 차이 칸은 굵기만 한 단계 더. **색은 셋 다 잉크색**. 모바일에서는 세 칸이 세로로 쌓임(가로 스크롤 금지)
   - 그 아래 서버 `summary` 문장 그대로
   - **세부 대조**: 정산액(작가 몫), 원천징수(3.3%) 두 줄을 작은 표로. 정산서에 없는 칸은 "정산서에 없음". 모바일에서는 표 대신 항목별 묶음(라벨 위, 숫자 셋 아래)
   - "이 기간 뒤 남은 MG" 한 줄
   - **계산 내역**: `<details>` **기본 접힘**, 제목 "계산 내역 12단계 보기". 펼치면 단계마다 [라벨 | 금액 | 식(작은 글씨, mono)]. `source_clause_id`가 있으면 "근거 · 제3조" 링크를 누르면 그 자리에서 `SourceQuote`로 조항 원문이 펼쳐짐(이미 불러온 `clauses` 사용, 새 API 호출 없음). 04 지시서의 "단계를 누르면 조항 원문" 요구사항
   - **플랫폼에 확인할 질문**: 번호 목록 + 오른쪽 위 "질문 복사" 버튼(클립보드에 줄바꿈으로 이어 붙여 복사, 복사되면 "복사했습니다"). 문장은 서버 것 그대로
5. **고정 안내**: `notice` + "계산 규칙 버전 2026-11-25-r13" 작은 글씨
6. **하단 행동**: "정산서 더 입력하기"(secondary), "계약서에 질문하기"(secondary)

**빈 상태**: 정산서가 없으면 `EmptyState` — "아직 입력한 정산서가 없습니다" + "정산서 입력하기"(primary)

### 5-2. 조건 확인 `/terms`

지금 문제: 카드 9개가 같은 무게로 세로로 늘어서 있고, 금액·비율 입력이 `3000000`, `0.65` 같은 개발자식이며, 근거 원문과 값이 떨어져 있습니다.

**구조**
1. **머리 카드**: "조건 확인" + 설명 "계약서에서 찾은 정산 조건입니다. 원문과 비교해 값을 확인해 주세요. **확인한 조건만 계산에 씁니다.**" + 진행 표시 "필수 조건 5개 중 3개 확인" (체크 개수 세기. 금액 계산 아님)
2. **섹션 둘로 나누기**: "계산에 필요한 조건 (필수)" — MG 금액, MG 회수 방식, RS 배분율, 정산 기준 매출, 공제 항목 / "참고 조건 (선택)" — MG 지급 시점, 미회수 MG 처리, 정산 주기, 정산금 지급 시점. 선택 섹션은 기본 접힘 없이 보이되 시각적 무게를 낮춤
3. **조건 카드**: 데스크톱(1024px 이상) 2단 — 왼쪽 = 조건 이름 + `StatusBadge` + 입력, 오른쪽 = `SourceQuote`(근거 원문). 모바일은 세로로 쌓되 **값 → 원문** 순서
   - 금액은 `MoneyInput`, 비율은 `RateInput`, 선택지는 지금처럼 `select`(스타일만 입힘)
   - `찾지 못함`이고 값이 비어 있으면: 카드 테두리를 점선으로, 문구 "계약서에서 이 조건을 찾지 못했습니다. 표준·일반 조건과 같다는 뜻이 아닙니다." 유지, 확인 칸 옆에 "값을 넣어야 확인할 수 있어요"를 보여 주고 확인 칸을 `disabled`. **단 `deductions`(공제 항목)는 빈 목록 + 확인 = "공제 없음"이라는 뜻이라 막지 않고** 문구를 "공제 항목이 없는 것으로 확인했습니다"로 바꿈
   - 구간별 RS 안내 문장 유지
   - 공제 항목은 줄마다 [이름 | 비율/금액 전환(세그먼트 버튼) | 값 | 삭제(ghost)]. 모바일은 두 줄
   - 확인 칸은 큰 체크 영역으로("계약서와 이 값을 확인했습니다"), 체크된 카드는 왼쪽에 brand 색 얇은 선. **체크 아이콘을 결과처럼 보이게 크게 쓰지 않음**
4. **아래 고정 바(sticky bottom)**: "필수 3/5 확인" · [저장](primary) · [정산서 입력으로 →]. `all_confirmed`가 아니면 정산서 버튼은 `disabled` + "필수 조건을 모두 확인하고 저장하면 열립니다". 저장 메시지(`message`)도 이 바 위에 표시
5. 처리 중 상태(계약서 읽는 중 폴링)는 `ProcessingState`로: "계약서를 읽는 중입니다. 보통 20초 안팎, 길면 1~2분 걸립니다. 끝나면 조건이 자동으로 나타납니다."

`save()`의 비교·검증 로직은 건드리지 않습니다. 입력 컴포넌트가 내보내는 값이 지금과 같은 문자열(`"3000000"`, `"0.65"`)이면 됩니다.

### 5-3. 정산서 입력 `/statements`

1. **입력 방법 탭**: "정산서 표 붙여넣기 (추천)" / "직접 입력". 붙여넣기 탭: 큰 textarea + "표에서 값 읽기" → 읽은 결과 표(원본 줄 / 항목 / 원본 값 / 안내)는 그대로 보여 주고, 폼이 채워졌다는 안내와 함께 폼으로 스크롤
2. **폼은 정산서 순서대로** 한 칸씩: 정산 기간(시작~끝) → 매출액 → 회사입금액 → 공제 항목 → 정산액 → 원천징수 → **작가지급액(필수, 가장 아래, 강조)**. 금액 칸은 전부 `MoneyInput`(매출액·회사입금액·정산액은 음수 허용). 각 칸 아래 지금의 힌트 문장 유지. "필수" 표시는 매출액·작가지급액·기간에만
3. 저장 버튼 문구: "이 달 정산서 저장"
4. **저장한 정산서**: 표(기간 / 매출액 / 작가지급액 / 삭제). 모바일은 카드 목록. 하나 이상이면 아래에 "대조 결과 보기 →"(primary)
5. 저장 후 폼 초기화와 메시지는 지금 동작 유지

### 5-4. 첫 화면 `/` (업로드 + 내 계약서)

1. **소개 한 줄**(머리): "계약서의 MG·RS 조건으로 정산서를 다시 계산해, 정산서 금액과 나란히 보여 드립니다." — 판단 표현 없이
2. **내 계약서가 있으면 목록을 위에**, 없으면 업로드 카드만
   - 행마다: 계약서 이름, 올린 날짜, 상태(`StatusBadge`와 같은 중립 스타일의 상태 라벨)
   - **주요 행동 버튼 하나만 크게**: `조건 확인 대기` → "조건 확인하기", `확정` → "대조 결과 보기", `처리중` → 스피너 + "읽는 중", `처리 실패` → "다시 올리기 안내". 나머지(조건·정산서·질문하기)는 작은 링크 묶음으로
   - 삭제는 `ghost` 버튼, 지금처럼 확인창 유지
3. **업로드 카드**
   - 입력 방식: 라디오 대신 세그먼트 버튼 "파일 올리기 / 본문 붙여넣기"

   - 개인정보 안내·동의는 지금 문구 그대로, 시각적으로 분명한 박스
   - 처리 중에는 버튼 대신 `ProcessingState`
   - 지금의 실패 처리(다시 시도 / 다른 파일 선택 / 본문 붙여넣기) 버튼과 로직 유지

```python
# /tmp/runapi.py  — 커밋하지 않음
import uvicorn
from openbook.api.main import app
from openbook.api.deps import get_llm, get_parser
from openbook.parsing import ParsedDocument
class FakeLLM:
    def complete(self, system, user): return "{}"
class FakeParser:
    def parse_file(self, filename, content, mime_type=None):
        return ParsedDocument(text=content.decode("utf-8", "ignore"))
app.dependency_overrides.update({get_llm: lambda: FakeLLM(), get_parser: lambda: FakeParser()})
uvicorn.run(app, port=8000)
```
